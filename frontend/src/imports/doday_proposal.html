01 · 문제 정의

왜 투두 앱을
결국 안 쓰게 될까?

Todoist, Notion, Things — 수많은 투두 앱이 있지만 대부분 결국 쓰지 않게 된다. 문제는 기록이 아니다. 기존 앱은 할 일 관리는 해줘도 할 일 실행을 도와주지 않는다.

문제 01
미루면 그냥 쌓인다
오늘 못 한 일은 빨간 줄로 표시될 뿐. 자동으로 내일 일정에 반영되지 않아 계속 방치된다.
문제 02
완료 체크가 귀찮다
할 일을 해도 앱을 열어서 완료 버튼을 누르는 걸 잊는다. 결국 미완료 항목이 쌓여 앱을 안 열게 된다.
문제 03
죄책감이 생긴다
미룬 항목이 빨간색으로 쌓일수록 앱 열기가 두려워진다. 도구가 오히려 스트레스 요인이 된다.
문제 04
폰과 PC가 따로 논다
데스크탑에서 작성한 할일이 폰에서 바로 보이지 않거나, 별도 앱 설치가 필요한 번거로움이 있다.
02 · 솔루션

Doday의
핵심 철학

미루는 걸 처벌하지 않는다. 대신 앱이 알아서 따라온다. 못 한 일은 자정에 자동으로 내일로 넘어가고, 마감 시간엔 알림 하나로 완료 처리가 끝난다.

기존 투두 앱
✕ 미루면 빨간 줄만 표시
✕ 완료 버튼 직접 눌러야 함
✕ 미룰수록 죄책감 증가
✕ 앱 열기가 두려워짐
Doday
✓ 자정에 자동으로 내일로 이월
✓ 마감 알림 탭 한 번으로 완료
✓ 이월해도 죄책감 없는 구조
✓ 앱이 알아서 따라와줌

04 · 기술 스택

면접에서
설명할 수 있는 코드

모든 기술 선택에는 이유가 있다. "왜 이렇게 짰어요?" 질문에 답할 수 있도록 각 기술이 서비스에 자연스럽게 녹아있다.

Must — 핵심
Spring Batch
매일 자정 미완료 이월 + 매주 월요일 주간 리포트 집계. Chunk 기반 처리, Job/Step 설계, 실패 재시작 전략까지 Batch의 정석 활용.
Chunk ProcessingJob/Step멱등성
Must — 핵심
Spring Security + JWT
구글 OAuth2 소셜 로그인, Access/Refresh Token 분리, Redis에 Refresh Token 저장. Security Filter Chain 구조 완전 이해 필요.
OAuth2JWTFilter Chain
Must — 핵심
JPA + QueryDSL
Todo-User 연관관계 설계, 이월 이력 테이블, N+1 방지(fetch join), 집계 쿼리. DTO↔Entity 분리, 지연로딩 설계까지.
연관관계N+1 방지QueryDSL
Must — 핵심
Redis
① Refresh Token 저장 (TTL 관리) ② 오늘의 할일 캐싱 (@Cacheable / @CacheEvict). 두 가지 활용처로 "왜 Redis 썼어요?" 설명 가능.
Token 저장캐싱TTL
Should — 차별화
Web Push + VAPID
PWA 기반 마감 알림. 앱 설치 없이 브라우저 푸시. VAPID 키 관리, 구독 정보 저장, 알림 스케줄링. @Async 비동기 발송.
VAPIDPWA@Async
Should — 차별화
LLM API 연동
주간 미룸 데이터 → 프롬프트 설계 → 코멘트 생성. 비동기 처리로 LLM 응답이 느려도 UX 영향 없음. 외부 API 클라이언트 구현.
프롬프트 설계비동기응답 파싱
Could — 완성도
테스트 코드
Batch Job 단위 테스트(@SpringBatchTest), Service 레이어 Mockito 테스트, MockMvc API 테스트. 포폴에서 보기 드문 차별화 포인트.
JUnit5Mockito@SpringBatchTest
Could — 완성도
GitHub Actions CI/CD
PR 머지 → 자동 빌드 → EC2 배포 파이프라인. Dockerfile, GitHub Secrets 환경변수 관리, RDS + ElastiCache 구성.
